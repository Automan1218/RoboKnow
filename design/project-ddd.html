🏢 14.6 Organisation Bounded Context
«Aggregate Root · PO»
OrganizationTag
table: organization_tags
PK tagId: String (human slug, immutable after creation)
name: String (display name)
description: String (TEXT)
parentTag: String → tagId (self-ref; null = root)
FK createdBy → User (ManyToOne)
createdAt / updatedAt: LocalDateTime
↩ parentTag (tree hierarchy; circular refs prohibited)
Multi-tenancy isolation rule:
FileUpload.orgTag → OrgTag.tagId
EsDocument.orgTag → OrgTag.tagId
ACL check: orgTag ∈ user.orgTags OR isPublic = true
Parent tag grants access to all child org documents
←
uses
← manages: OrganizationTag AR
Domain Services
OrgTagCacheService — caches tag hierarchy in Redis
OrgTagInitializer — seeds default tags on startup
OrgTagAuthorizationFilter — HTTP filter for data-level auth
Business Rules
BR-1: tagId immutable after creation
BR-2: Root tags (parentTag == null) = top-level departments
BR-3: Circular parent references prohibited
BR-4: Deleting tag with children requires reassignment first
BR-5: PRIVATE_<username> auto-created on registration; not deletable

Business Rules

BR-5: LTM write skipped if answer = "no result" signal
BR-6: Stop flag checked at start of each ReAct iteration
Cross-Domain Relationships
All 5 contexts share one MySQL schema (monolith). Kafka is the only async boundary.
FromToFieldCard.TypeNotes
Organisation · OrgTag Identity · User createdBy → User N:1 JPA @ManyToOne Each org tag has one creator. Hard FK enforced by JPA.
Document · FileUpload Identity · User userId → User.id N:1 Logical String FK No JPA annotation. App layer resolves userId string.
Document · FileUpload Organisation · OrgTag orgTag → tagId N:1 Logical String FK Scopes file to one org. Propagated to ES for ACL filter.
Document · FileProcessingTask Knowledge · EsDocument fileMd5 correlation key 1:N Kafka async event Upload → publish → Consumer: parse → embed → index N EsDocuments (one per chunk).
Knowledge · EsDocument Document · FileUpload fileMd5 → FileUpload N:1 Natural key join SearchResult enriched with fileName via MySQL JOIN on fileMd5 after ES hit.
Knowledge · EsDocument Knowledge · DocumentVector vectorId = ES _id 1:1 Natural key DocumentVector (JPA) mirrors EsDocument reference; used to delete ES doc on file removal.
Conversation · Conversation Identity · User user → User N:1 JPA @ManyToOne LAZY Index on (user_id, timestamp) for history queries.
Chat/Agent · ChatHandler Knowledge · HybridSearchService SearchRequest VO → SearchResult VO 1:N / query Sync call RAG: question → embed → kNN + BM25 → inject as LLM context.
Chat/Agent · AgentContext Conversation · ConversationService conversationId 1:1 / session Sync call Agent reads history for ReAct context. Writes back on FINISHED state.
Chat/Agent · HybridSearchTool Knowledge · HybridSearchService ToolRegistry.dispatch() 1:N / step Sync call ACTING state → ES query → Observation returned to ReAct loop.
